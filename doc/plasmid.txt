1. INTRODUCTION                                                *plasmid-intro*

Opening a GenBank, FASTA or SnapGene file shows a rendered, read-only view of
the sequence instead of its raw text. The underlying record model is the
source of truth; |:w| serialises it back to disk. Residues and features can
be edited (|plasmid-editing|, |plasmid-features|), every change is one undo
step, and features follow the bases they annotate.

==============================================================================
2. VIEWS                                                       *plasmid-views*

Linear ~
  Sequence rows with base-pair numbers at both ends, residues grouped by ten,
  the complement strand, feature tracks (arrowheads mark the 3' end, dashed
  segments mark introns), and, under each CDS, its translation aligned to the
  middle base of each codon.

  Residues are grouped by ten by default. `linear.group = 0` (or |:DnaGroup|)
  shows them continuously, with a ruler row numbering every 10th residue, so
  no codon is ever split by a gap and each residue sits under the middle of
  its codon at an even spacing of three. Other group sizes are accepted;
  line widths stay multiples of 10 and of the group size.

  With the cursor on an amino acid, its codon is highlighted on both strands
  (|hl-PlasmidCodon|), including codons split by a line break, an intron or
  the origin, and the winbar shows e.g. "codon 55/397 ATG→M 248..250".

Circular ~
  A braille-dot plasmid map. The origin is at 12 o'clock and numbering runs
  clockwise. Features are arcs on rings inside the backbone; labels sit outside
  with leader lines. Moving the cursor over the ring or a label reports the base
  pair and feature in the winbar.

The header counts annotated features; detection proposals and ORFs are listed
separately ("9 features · 2 proposed · 3 ORFs").

==============================================================================
3. CROWDED REGIONS                                          *plasmid-priority*

When features overlap, each one gets a score and the highest scores are placed
first, nearest the sequence:

  score = priority.types[type] (or priority.default)
          + priority.labelled_bonus   if the feature has a real name
          + priority.pinned_bonus     if you added or accepted it this session

Ties go to the longer feature. The linear view draws at most
`linear.max_tracks` feature rows per line; anything that did not fit is
summarised under the line as "+N more: type, ...". Placement is decided per
line, so a feature hidden in one crowded line still appears where there is
room. `+` shows every track, `-` returns to the limit, and |:DnaTracks| sets a
limit for the buffer. The circular map uses `circular.max_tracks` rings and
reports "n over ring limit" in its header.

==============================================================================
4. SELECTION                                               *plasmid-selection*

A selection is a range of base pairs held by the plugin, independent of the
text on screen, so it survives view switches and works across line breaks.

  vaf  yaf    Text object: the whole span of the feature under the cursor.
  vif  yif    Text object: the feature's own residues, spliced (join) and read
              5'->3' on its strand. `yif` on a reverse-strand CDS yanks the
              coding sequence starting with its start codon.
  v ... y     Visual mode: yank the bases under the selection (top strand).
  v ... Y     Visual mode: yank the reverse complement (bottom strand 5'->3').
  v ... gy    Visual mode: choose the strand and direction (below).
  gy  gY      Yank the current selection (gY: reverse complement).
  <Esc>       Clear the selection.

Strand and direction ~                                      *plasmid-strands*
Visual `gy` and |:DnaYank| without an argument offer four orientations, each
with a preview:

  top        top strand 5'->3'           (as displayed on the top row)
  top35      top strand 3'->5'           (reversed)
  bottom     bottom strand 5'->3'        (reverse complement)
  bottom35   bottom strand 3'->5'        (complement, as displayed)

For an inner feature selection (`vif`) the residues are spliced first and the
feature's own strand is marked in the list.

Yanks contain residues only, never display text, in the case the view shows
(`linear.case`: upper case for GenBank/SnapGene, FASTA soft-masking kept).
The winbar shows the selection's range and length. See also |:DnaSelect|.

Clipboard ~                                               *plasmid-clipboard*
A plain yank (no register given) goes to the unnamed register and to the
system clipboard ("+"), so it can be pasted into other programs. A named
register (`"ay`, `:DnaYank bottom a`) stays inside Neovim; `"+` and `"*` go to
the clipboard. `yank_clipboard` changes this: true (default) = "+", "auto" =
follow 'clipboard' (unnamedplus -> "+", unnamed -> "*"), false = never.

The copy uses Neovim's clipboard provider when one exists (xclip, xsel,
wl-copy, pbcopy, win32yank, |g:clipboard|). Without one, and with a terminal
attached, it is sent to the terminal as an OSC 52 escape sequence, which most
terminals turn into a clipboard copy, also over SSH (kitty, WezTerm, iTerm2,
Alacritty, foot, Windows Terminal; tmux needs `set -g set-clipboard on`).
|:checkhealth| plasmid reports which path is in use.

==============================================================================
5. ADDING AND EDITING FEATURES                              *plasmid-features*

  ga          Add a feature over the selection (or visual range). Prompts for
              label, type and strand. On a proposal or ORF with nothing
              selected, accepts / promotes it instead.
  gE          Edit the feature under the cursor in a scratch buffer: first
              line TYPE LOCATION in GenBank syntax, then /qualifier=value
              lines. |:w| applies, |:q| discards.
  u  <C-r>    Undo / redo feature changes (each add, edit, delete, accept or
              batch accept is one step).

Features you add are "pinned": they win space in crowded regions until the
file is reopened. New features are written as GenBank qualifiers; in a SnapGene
file the Features packet is regenerated, keeping every untouched feature's XML
verbatim. FASTA cannot hold features: writing one warns that feature changes
are not saved (write to a .gb name to keep them).

Personal library ~
|:DnaFeatureSave| stores the feature under the cursor (or the selection) in a
GenBank file, one record per feature (`library_path`, default
stdpath("data")/plasmid/library.gb). |:DnaDetect| always searches it, so
elements you save once are found again in other plasmids.

==============================================================================
6. SEQUENCE EDITING                                          *plasmid-editing*

The plasmid view stays read-only text; edits go through the record, so
annotations move with their bases. Every edit is one undo step (`u`, `<C-r>`),
and the winbar shows "unsaved" until |:w|.

Keys (cursor base = the base pair under the cursor, in either view) ~
  i  a        Insert residues before / after the cursor base (prompt).
  [count]x    Delete bases from the cursor.
  [count]r{c} Replace bases with the letter {c}.
  p  P        Insert register contents after / before the cursor base.
  v ... d  x  Delete the selected bases.
  v ... c     Replace the selected bases (prompt).
  v ... p     Replace the selected bases with register contents.
  v ... R     Reverse-complement the selected bases in place.
  daf  dif    Delete the feature under the cursor (dif: only its own parts,
              e.g. the exons of a spliced CDS).
  caf         Replace the feature's span (prompt).
Deleted residues go to the unnamed register and "1, as with Vim's x and d, so
`xp` swaps two bases. Letters are checked (IUPAC nucleotide codes, or amino
acids in protein records); digits, spaces and "/" are ignored, so ORIGIN text
from a GenBank file can be pasted. New residues follow the record's case and
its T/U convention.

How features follow an edit ~
  - Deleted bases leave every feature; a feature losing all its bases is
    removed.
  - An insertion strictly inside a feature extends it; at its first base or
    after its last base it shifts the feature instead. On a circular record an
    insertion at the origin extends a feature that crosses it.
  - Replacement bases belong to the features that covered the bases they
    replace.
  - Reverse-complementing a region flips the strand of features wholly inside
    it; features only partly inside keep their coordinates.
  - |:DnaRotate| splits features crossing the new origin into a join and
    merges a former origin-crossing pair.

Impact report ~
After each edit a message summarises what happened to the features, and
|:DnaEditReport| lists them all: truncated, extended, destroyed, bases changed,
and for CDS features FRAMESHIFT, a new stop codon, a lost start or stop codon,
the number of changed amino acids (or "silent"). `/translation` of a changed
CDS is rewritten, or removed when the coding sequence now contains a stop
codon (`edit.update_translations`). Features cut by a deletion are handled per
`edit.cut_policy`:
  "truncate"  report only (default)
  "flag"      also add a /note to the truncated feature
  "refuse"    cancel the edit; commands with ! (and |:DnaEdit| with :w!) force it
Proposals from |:DnaDetect| are cleared by an edit (run it again); ORFs are
recomputed.

:DnaEdit ~
Opens a range (default: the selection) as an ordinary buffer, 60 residues per
line: every Vim motion, search, macro and Vim's own undo work there. |:w|
compares the text with the original residues and applies only the differences
(insertions, deletions, replacements) as one change, so features inside the
region keep their bases; |:q| discards. If the record's sequence changed while
the buffer was open, the write is refused. Regions crossing the origin of a
circular record are refused (rotate first).

Saving ~
GenBank: ORIGIN and the LOCUS length are rewritten, BASE COUNT is dropped,
features that only moved get new location lines and keep their original
qualifier lines. FASTA keeps its line width. A file opened from SnapGene
(.dna) cannot be written back once its residues changed: save it as GenBank
(`:w name.gb`).

==============================================================================
7. OPEN READING FRAMES                                          *plasmid-orfs*

`go` (or |:DnaOrfs|) overlays open reading frames on all six frames. Each ORF
is the longest one ending at its stop codon, starting at the first in-frame
start codon. Defaults: ATG starts, at least 75 aa, the record's /transl_table
or else code 11 for circular and code 1 for linear records. ORFs may cross the
origin of circular records. ORFs ending at the stop codon of an annotated CDS
are hidden (`orfs.hide_annotated`). ORFs are drawn with their translation;
`ga` or |:DnaOrfAdd| on one turns it into a CDS feature.

==============================================================================
8. FEATURE DETECTION                                          *plasmid-detect*

|:DnaDetect| searches the record for known elements and draws matches as
proposals (italic, |hl-PlasmidProposed|). Nothing is added until you accept:

  ga / :DnaDetectAccept           accept the proposal under the cursor
  :DnaDetectAccept!               accept every full-length proposal
  :DnaDetectAccept! fragments     ... and partial matches too
  :DnaDetectReview                pick proposals from a list
  :DnaDetect off                  remove the proposals

An accepted feature carries the reference's description as /note and a second
/note recording the source, e.g. "detected by plasmid.nvim: snapgene/AmpR,
100.0% identity, 100% of the reference". Partial matches keep "(fragment)" in
their label.

Search ~
References of 20 bp or more are found by shared 12-mers followed by banded
Smith-Waterman alignment on both strands, across the origin of circular
records; shorter ones (primer sites, tags) by exact search on both strands. A
full-length hit needs `detect.min_identity` (0.95) and `detect.min_coverage`
(0.95 of the reference); partial hits need `min_fragment_coverage` (0.5) and
`min_fragment_length` (50 bp). A hit lying inside a better hit of the same
type is dropped unless `nested_same_type` is true.

Databases ~
No database ships with the plugin. Import one with |:DnaFeatureDbImport|;
imported data is kept under `featuredb_dir` (default
stdpath("data")/plasmid/featuredb) as FASTA + TSV.

pLannotate's SnapGene-derived set (GPL-3; https://github.com/mmcguffi/pLannotate)
                                                          *plasmid-plannotate*
  1. Download plannotate-databases-v2.tar.gz from the pLannotate releases and
     unpack it.
  2. :DnaFeatureDbImport /path/to/BLAST_dbs
     This reads snapgene.* with `blastdbcmd` (NCBI BLAST+ must be on PATH) and
     the descriptions from the bundled SQLite file (`sqlite3` or Python).
     About 1,370 references are imported.
  Without BLAST+, export the sequences yourself and import FASTA + CSV:
     blastdbcmd -db BLAST_dbs/snapgene -entry all > snapgene.fasta
     :DnaFeatureDbImport snapgene.fasta snapgene descriptions.csv

Other sources ~
  :DnaFeatureDbImport {file.fasta} [name] [descriptions.csv]
      FASTA headers ">id" or ">id name"; the optional CSV maps id to
      name/type/description (pLannotate columns sseqid,Feature,Type,
      Description are recognised, as are common aliases).
  :DnaFeatureDbImport {file-or-folder} [name]
      GenBank (.gb .gbk .gbff .genbank .ape) or SnapGene .dna files; every
      annotated feature of 8 bp or more (except source) becomes a reference.

|:DnaFeatureDbList| shows imported databases; `:DnaDetect {name} ...` limits
the search to named databases.

==============================================================================
9. SEARCH                                                     *plasmid-search*

/  ?       Prompt for a motif and search forward / backward. Type
            "GGTCTC" for exact matches, "GGTCTC 1" to allow one mismatch,
            "aa:MSIQHF" for amino acids (six-frame translation, or the
            residues of a protein record).
n  N       Next / previous hit (in the direction of the search; counts
            work).
gn         Select the current hit (then |plasmid-selection| keys, edits
            or :DnaEdit apply to it).

IUPAC codes in the motif match the bases they stand for (R = A or G, N = any).
A sequence letter matches only when every base it may be is allowed: an N in
the sequence matches an N in the motif and nothing else. Both strands are
searched; a palindromic site is reported once. Circular records are searched
across the origin. Hits are highlighted on the strand they lie on (bottom-
strand hits on the complement row), marked outside the backbone on the
circular map, and counted in the winbar ("/GGTCTC 2/25"). They are searched
again after every edit and undo.

:DnaFind {motif} [mismatches]                                     *:DnaFind*
:DnaFind! {motif} [mismatches]  Search; ! searches backwards.
:DnaFind off                    Clear the hits.

10. RESTRICTION ENZYMES                                      *plasmid-enzymes*

gz         Show / hide restriction sites (`enzymes.default_set`, "unique").
gZ         List every enzyme with its number of sites; choosing one adds it
            to (or removes it from) the named set.
K  <CR>    On an enzyme label: site, cuts on both strands, overhang, number
            of sites, and a Dam/Dcm warning where it applies.

Sets: "unique" (one site), "dual" (one or two), "all" (every cutting enzyme)
consider enzymes with at least `enzymes.min_site` specific letters (6), and
leave out DpnI, which only cuts methylated DNA. Named sets show exactly the
enzymes named. Enzymes that cut at the same place share one label.

Linear view: a label "▏EcoRI" puts its bar on the left edge of the base after
the top-strand cut, i.e. on the cut; "EcoRI▕" (used when the label must go
left) puts it on the right edge of the base before the cut. A row under the
complement marks bottom-strand cuts, so 5' and 3' overhangs show as a stagger.
Sites are underlined. At most `enzymes.lanes` label rows are used per line;
the rest are counted as "(+n)". Circular view: cut ticks cross the backbone
and labels are placed around the map after feature labels.

Methylation: an enzyme flagged as Dam- or Dcm-sensitive warns when a GATC or
CCWGG overlaps its site. Flags come from NEB's published sensitivity
information and are present for 41 of the 222 bundled enzymes only; no
warning does not mean the enzyme is insensitive.

Enzyme data ~                                                *plasmid-rebase*
The bundled table holds 222 common commercial Type II enzymes (palindromic,
degenerate and Type IIS), each checked against Biopython's Bio.Restriction.
For the full REBASE set, download the EMBOSS-format files from REBASE
(emboss_e.NNN, optionally emboss_r.NNN and emboss_s.NNN) and import them.
Enzymes with two cut pairs or no defined cut are skipped. The import is
stored in stdpath("data")/plasmid/rebase_enzymes.json and is used instead of
the bundled table until cleared. With supplier data, the unique/dual/all sets
keep to commercially available enzymes (`enzymes.commercial_only`). REBASE
data is not distributed with the plugin.

Digests ~                                                    *plasmid-digest*
:DnaDigest lists the fragments of a digest in a split: span, length, both
ends with their overhang ("EcoRI 5′ AATT", "PstI 3′ TGCA", "blunt") and the
features each contains ("…" marks a cut feature), with a gel lane below. In
that window:
  <CR>     Select the fragment in the plasmid view.
  e        Open the fragment as a new linear GenBank record: the top strand
           from its left cut to the base before its right cut. Whole features
           are kept, cut ones truncated (the editing rules,
           |plasmid-editing|). :w saves it next to the source.
  q        Close.
The table refuses to act once the sequence has changed; digest again.

:DnaGel draws one lane per digest next to a 1 kb or 100 bp ladder (chosen
from the sizes, or `ladder=1kb` / `ladder=100bp`). Bands are placed on a log
scale; fragments that migrate together are marked ×n; sizes outside the
ladder are listed below. Uncut circular DNA is drawn at its linear size;
supercoiled and nicked forms are not modelled. A lane whose enzymes are
preceded by `partial` is the partial ladder below.

Partial digests ~                                    *plasmid-partial-digest*
A digestion that did not go to completion leaves any span bounded by two cut
sites, or by a cut and the end of a linear molecule. :DnaDigestPartial lists
all of them, with a "missed" column counting the sites inside each fragment
that were not cut: the complete-digest fragments are the ones that missed
none. The table and its gel lane say that the ladder is the whole set of
possible bands, not what one reaction yields.

The answer grows as the square of the site count — n sites on a circle bound
n² spans (n of them the whole molecule, linearised at one site) and leave the
intact circle, and n sites on a linear molecule bound (n+2)(n+1)/2 spans over
its n+2 boundaries. Above `digest.partial.max_sites` (12, which is 145
fragments) the command reports how many there would be instead of listing
them; `digest.partial.max_fragments` (500) caps the table, which is then
filled with the fragments that read through fewest sites.

A partial fragment behaves like any other: <CR> selects it, `e` extracts it,
and gA stages it as a cloning part whose source reads "partial digest of X
(2 sites uncut)".

:DnaEnzymes [set]                                               *:DnaEnzymes*
                                unique | dual | all | off | pick |
                                Enzyme ... ; no argument toggles.
:DnaEnzymeImport {emboss_e} [{emboss_r} [{emboss_s}]]     *:DnaEnzymeImport*
:DnaEnzymeImport clear          Back to the bundled table.
:DnaEnzymeImport                Show which table is in use.
:DnaDigest [Enzyme ...]                                          *:DnaDigest*
                                Digest; default: the named set shown.
:DnaDigestPartial [Enzyme ...]                            *:DnaDigestPartial*
                                Every fragment an incomplete digestion can
                                give, with its ladder.
:DnaGel {digest} | {digest} ... [ladder=1kb|100bp]                  *:DnaGel*
                                A digest is a list of enzymes, "uncut", or
                                "partial" followed by enzymes.

11. PRIMERS                                                  *plasmid-primers*

gp         Visual: make a primer from the selection (forward or reverse).
K  <CR>    On a primer: sequence, annealing, Tm, structures, binding sites
            and the best facing pair with its Ta.

A primer binds where its 3'-terminal 10 bases match the template exactly. The
annealed region then extends towards its 5' end across mismatches - a changed
codon, say - as long as at least 5 matching bases follow; whatever is left
over at the 5' end is a tail (restriction site, Gibson overlap, ...). The rule
reproduces SnapGene's own annealing calls on 19 of the 20 primer sites in the
test files. Tune it with `primers.binding` (|plasmid-config|).

Primers are drawn base by base over the template they copy: forward primers
above the sequence, reverse primers below the complement, tails in lowercase,
mismatched bases highlighted, and the name at the 3' end ("›M13fwd",
"M13rev‹"). At most `primers.lanes` rows are used per line and per side.
`primers.show = false` draws them as ordinary features instead.

The full oligo is kept: SnapGene files store it in their primer record, and
in GenBank it is written as /note="primer sequence: ...". Primers read from
either come back with their tails intact.

:DnaPrimerAdd {sequence} [name]                               *:DnaPrimerAdd*
:DnaPrimerAdd [fwd|rev] [name]  From the selection (fwd = top strand).
                                With several binding sites, pick one or all.

Melting temperature ~                                             *plasmid-tm*
:DnaTm {seq} [{seq2}] [polymerase=] [dmso=] [conc=] [salt=]            *:DnaTm*
                                Tm; with two sequences also the annealing
                                temperature. No sequence: the selection.
:DnaPolymerase [key]                                           *:DnaPolymerase*
                                Choose the polymerase (picker without
                                argument); it applies to every Tm shown.

The model is the NEB Tm Calculator's: SantaLucia 1998 nearest-neighbour
thermodynamics, Owczarzy 2004 salt correction (Schildkraut-Lifson with
conc/4 for Phusion), each product's buffer salt, primer concentration, Ta
rule and cap, and -0.6 degC per % DMSO. 22 NEB products are built in. The Lua
port came from polymerase-tm (MIT) and was checked against NEB's own Tm API:
5,940 Tm values (22 products) and 2,580 Ta values (the 19 with a Ta rule)
with no mismatch (docs/tm_report.md).
`method = "owczarzy2008"` with `mg_mM` applies the Mg-aware correction used
for site-directed mutagenesis primers.

Oligo structures ~                                             *plasmid-oligo*
The primer float also reports GC content, the 3'-terminal G/C count, the
longest homopolymer run, 3'-end stability and hairpin / self-dimer /
cross-dimer free energies, computed with SantaLucia & Hicks 2004 parameters.
These are estimates, not primer3's numbers: over ~3,900 oligos the free
energies correlate with primer3 at r = 0.96-0.99 (median error 0.4 kcal/mol)
and the two agree on whether to warn in 93.0-99.1 % of cases; 3'-end
stability is exact. docs/oligo_report.md has the tables.

Design ~                                                      *plasmid-design*
:DnaPrimerDesign [name=] [tm=] [len=18-30] [slack=] [dtm=]  *:DnaPrimerDesign*
                [fwd=Enzyme|SEQ] [rev=Enzyme|SEQ]
                                Rank primer pairs for the selection.

Candidates vary in length and may start up to `slack` bases outside the
selection; the product then grows but the selection stays inside it, which is
what makes a Tm match possible at a GC-rich boundary. Each primer is scored on
its distance from the target Tm, GC content, a 3'-terminal G/C, homopolymer
runs, hairpin and self-dimer free energy and whether it binds the template
only once; pairs are scored on the Tm difference between them. `fwd=EcoRI`
adds that recognition site as a 5' tail (no protective bases are invented).
Choosing a pair adds both primers in one undoable step. When nothing fits, the
message names the Tm range that side can actually reach, or the closest Tm
difference available.

PCR ~                                                            *plasmid-pcr*
:DnaPCR [primer1] [primer2]                                           *:DnaPCR*
                                Primer names or sequences; with none, the
                                record's own primers.

Products are found on linear and circular templates, including across the
origin, and opened as a new linear record: 5' tails and primer mismatches are
written into the product, the template's features come along (truncated where
the product cuts them, |plasmid-editing|), and both primers are re-annotated
full length. :w saves it next to the source file. Products agree with pydna
on 232 of 232 amplifying pairs and on 8 of 8 non-amplifying ones.

12. NCBI FETCH                                                 *plasmid-fetch*
                                                                *plasmid-ncbi*
Records are downloaded from NCBI's E-utilities with `curl` (asynchronously;
Neovim stays usable) and open in a new, unsaved buffer named after the
accession, in `fetch.dir` or the current directory. `:w` keeps the file.

:DnaFetch[!] {acc}[:{from}-{to}][:-]                               *:DnaFetch*
                                Open a record. Nucleotide accessions come as
                                GenBank with all parts (contig records include
                                their sequence); protein accessions (NP_, XP_,
                                UniProt such as P69905, PDB chains such as
                                4HHB_A) as GenPept. GI numbers and accessions
                                without a version resolve to a versioned
                                accession, shown in the message and the file
                                name. {from}-{to} fetches only that region,
                                renumbered from 1; a trailing :- gives the
                                reverse complement. ! re-downloads (ignoring
                                the cache) and lifts `ncbi.max_length`.
                                Prefix "protein:" or "nuccore:" to force the
                                database.
:DnaFetch cancel                Stop running requests.

:DnaSearch[!] {query}                                             *:DnaSearch*
                                Entrez search of nuccore (! protein), e.g.
                                `pBR322[title] AND complete sequence[title]`.
                                Lists up to `fetch.search_results` hits with
                                length, topology and title; pick one to open.

:DnaGene {symbol} [organism] [flank=N] [plus]                       *:DnaGene*
                                Look the symbol up in NCBI Gene (organism
                                defaults to `fetch.organism`, else human) and
                                fetch the gene's genomic region. Minus-strand
                                genes are reverse-complemented so the gene
                                reads 5'->3'; `plus` keeps the reference
                                strand. flank=N adds N bases on each side.

:DnaFetchCache [clear]                                       *:DnaFetchCache*
                                List or empty the cache
                                (stdpath("cache")/plasmid/ncbi, kept
                                `ncbi.cache_days`).

Links ~                                                    *plasmid-gF*
On a feature with /protein_id, /db_xref="GeneID:..." or a UniProt cross
reference, |K| shows a `links` line and `gF` opens the linked record (for a
gene, its region).

Size guard ~
Before downloading, the record's length is checked against `ncbi.max_length`
(5,000,000) so a chromosome accession does not pull hundreds of megabytes.
Fetch a sub-range, or use :DnaFetch!.

Rate limits and privacy ~
Requests are spaced to NCBI's limit of 3 per second, or 10 per second with an
API key (`ncbi.api_key` or $NCBI_API_KEY), and retried with backoff on HTTP
429 and transient server errors. No e-mail address is sent unless you set
`ncbi.email`; NCBI's usage guidelines ask heavy users to set both. The key is
passed to curl on standard input, never on its command line.

13. CLONING                                                  *plasmid-cloning*

Gibson/HiFi, Golden Gate and restriction-ligation, on top of the digest and
PCR machinery. Parts are staged, then assembled; the product opens as a new
unsaved record and a report split explains the result.

Staging ~
:DnaCloneAdd [name]                                             *:DnaCloneAdd*
                                Stage a part: in a digest table the fragment
                                under the cursor (or fragment N when the
                                argument is a number), in a sequence buffer
                                the selection, else the whole record. [name]
                                labels the part. Mapped to gA.
:DnaCloneList                   The staged parts with their      *:DnaCloneList*
                                lengths and ends.
:DnaCloneClear                  Empty the list.                 *:DnaCloneClear*
:DnaCloneTreat {treatment} [part ...] [left|right]            *:DnaCloneTreat*
                                End chemistry on staged parts
                                (|plasmid-end-chemistry|). Without a part
                                every staged part is treated, without a side
                                both ends are.

End chemistry ~                                       *plasmid-end-chemistry*
A fragment's ends carry more than their overhang, and :DnaCloneTreat changes
it. The treatment is recorded on the part, so the part list and the assembly
report name it.

  fillin    Klenow or T4 polymerase with dNTPs. Extends the recessed strand
            of a 5′ overhang until the end is blunt; the overhang bases stay,
            so the fragment keeps its length. A 3′ overhang is not touched.
  chewback  T4 polymerase without dNTPs. Removes the protruding bases of a
            3′ overhang; the fragment loses them. A 5′ overhang is not
            touched.
  blunt     T4 polymerase with dNTPs: fillin on a 5′ overhang, chewback on a
            3′ one. This is how blunting is usually done at the bench.
  nuclease  Mung bean or S1. Removes whichever single strand protrudes, 5′ or
            3′; the fragment loses those bases.
  dephos    CIP, rSAP or Antarctic phosphatase: clears the 5′ phosphate.
  kinase    T4 polynucleotide kinase: puts it back.

A blunt end is changed by none of them. Where an end moves the record moves
with it: features that reached into the removed bases are truncated by the
editing rules (|plasmid-editing|), and a treatment that would leave nothing
double-stranded is refused.

Sealing a junction makes two nicks, one per strand, and ligase needs a 5′
phosphate beside each 3′ hydroxyl. The two phosphates come from the two ends,
one each, so one phosphorylated end per junction is enough — the product then
carries a nick the cell repairs. With neither there is nothing to seal, which
is why a dephosphorylated vector stops self-ligating but still takes an
insert. A restriction digest leaves both ends phosphorylated, so nothing
changes until you dephosphorylate; `cloning.require_phosphate = false` turns
the rule off. An end with no phosphate reads "5′ AATT, no 5′ P" in the part
list, and a junction that fails for that reason says so in the report.

Assembling ~
:DnaClone [parts ...]           Assemble; the method is inferred.   *:DnaClone*
:DnaLigate [parts ...]          Join by ends, sticky or blunt.     *:DnaLigate*
:DnaGoldenGate [enzyme] [parts ...]                            *:DnaGoldenGate*
                                One-pot Type IIS assembly; the enzyme
                                defaults to `cloning.enzyme` (BsaI).
:DnaGibson [parts ...]          Join by terminal homology.         *:DnaGibson*

A part argument is a staged part, the word `selection`, a digest fragment
number, an open buffer (by record or file name), or a file path. With no
arguments the staged list is used, else the fragments of the current digest.

:DnaClone picks Golden Gate when every part carries a site for one Type IIS
enzyme, Gibson when parts share terminal homology of at least
`cloning.min_homology`, otherwise ligation.

What is modelled ~
Two ends anneal when they are the same length, lie on opposite strands and
read the same along the top strand; blunt ends always ligate. Fragments may be
used in either orientation, so blunt parts give two products and a picker;
distinct overhangs or homology arms give one. Gibson joins are exact terminal
matches, longest first, between `cloning.min_homology` and
`cloning.max_homology` bases. Partial overlaps, chew-back and fill-in are not
modelled, and ends of different lengths never anneal.

Every part's features are carried into the product and remapped; a feature
that a cut had split is re-joined when the assembly puts it back together.
Each part and each junction is annotated unless `cloning.annotate_parts` or
`cloning.annotate_junctions` is false.

The report ~
On success: the parts in order with length, orientation and ends; every
junction with its overhang or overlap; the features carried; and warnings --
Golden Gate parts with no site or with several site-free pieces, overhangs
that are palindromic, unpaired, of different lengths or used more than twice,
a product that stayed linear, parts that contributed nothing.

When nothing assembles the report lists every ordered pair of ends and the
reason it was refused (a 5' overhang cannot anneal to a 3' overhang, the
overhangs are not complementary, a blunt end and a 4 base end), with a hint
for the method in use.

The bench plan ~                                           *plasmid-clone-plan*
:DnaClonePlan[!] [path]                                        *:DnaClonePlan*
                                The plan for the last assembly, in a split;
                                with a path (or !) also written to a file.
                                ! writes beside the source record, named after
                                the product.

The report split and the file hold the same text: the parts and where each
came from, how each was prepared and its ends; the reaction and its enzyme;
the expected product with every junction and the base it sits at; the
by-products; a diagnostic digest with the gel it gives; a colony-PCR pair for
each junction sized on the product and on every by-product; and a sequencing
primer each way across each junction.

By-products are molecules the assembler really builds, from the same
fragments: one part closing on itself, a part left out, the same parts in
another order or orientation, a part taken twice, and -- for a part that went
in as a circle -- that circle carried through uncut. `cloning.plan.max_parts`
(6) bounds the enumeration; above it only the largest proper subsets are tried
and the plan says what was skipped. Duplicates are removed by molecule, so a
rotation or the reverse complement of the product is never listed as
background.

The diagnostic digest searches single enzymes, then pairs, stopping at the
first size that answers cleanly. `cloning.plan.max_enzymes` (2) is the largest
set offered; raise it to 3 to search triples as well. The candidates are every
enzyme in the active set whose site has at least `cloning.plan.min_site` (6)
specific bases, less those that need methylated DNA. Two lanes are told apart
only when one has a band in a gel row the other has not, as
the gel model places them (|plasmid-digest|): two sizes in one row are one
band, and a band off the end of the gel shows nothing. `cloning.plan.min_gap`
(2) is how many rows a distinguishing band must clear; a set that
discriminates only by a band next to its neighbour is reported with that
caveat and a pair is searched for instead. A set that leaves a molecule uncut
is reported too, since an uncut circle does not run at its linear size; a set
that cuts the product is preferred over one that leaves it whole.

When no set discriminates, the plan says so, names the by-products nothing
distinguished, and offers the best partial check as a partial check. A digest
that cannot tell two outcomes apart is worse than none, because it will be run
and believed.

Colony-PCR pairs and sequencing primers come from |:DnaPrimerDesign|'s own
search over a window around each junction, so the pair spans the junction and
the read starts `cloning.plan.read_offset` (150) bases before it. Sizes on
each by-product come from |:DnaPCR|; a pair that gives the same size on the
product and on a by-product is reported as not a check.

What the plan does not model: band intensity (so a doubled band is not
evidence), partial digestion, star activity, supercoiling, and how well each
molecule transforms. The by-products are what the parts can give, not what
they will give.

Primers for an assembly ~                                *plasmid-clone-design*
>vim
  :DnaPrimerDesign name=tet into=pBR_dest enzyme=BsmBI
  :DnaPrimerDesign name=tet into=pVec_linear homology=25
<
`into=` takes the tails from the destination: its terminal bases for Gibson,
or the enzyme site, spacer and the fusion overhangs its own cut leaves for
Golden Gate. `overhangs=AATG/GCTT` sets them by hand, `method=` forces the
choice. A site for that enzyme inside the region to amplify is flagged, and
the pair you choose is amplified and assembled to confirm that it closes.

Limits ~
The search enumerates orderings; `cloning.max_solutions` (default 50) bounds
it. With many interchangeable ends -- a one-enzyme digest of several fragments
-- the orderings reported are the first 50 found, and exhaustive enumeration
is only practical up to about 8 such fragments. A defined design prunes to one
path: a 12-part Golden Gate searches in under a millisecond. Cutting is the
cost on large records: budget roughly 60 ms per fragment when a few hundred kb
is cut into many pieces. docs/cloning_report.md has the measurements and the
comparison with pydna.

14. ALIGNMENT                                                  *plasmid-align*

Pairwise alignment with affine gaps: place a sequencing read on the record,
place a whole run of reads, or compare two molecules end to end. Differences
are reported in the record's coordinates, with the feature and codon they hit.

:DnaAlign {query} [mode=] [strand=] [name=]                        *:DnaAlign*
                                Align a query against the record and open the
                                alignment view. {query} may be residues typed
                                inline, a file, an open buffer, a staged
                                cloning part, a digest fragment number, or
                                `selection`.
:DnaAlignReads {file|glob} ...                                *:DnaAlignReads*
                                Place every record of every file and list them
                                by position: strand, span, identity,
                                differences, coverage. <CR> opens one. Reads
                                that do not place are listed with the reason.
:DnaCompare {record} [mode=] [name=]                             *:DnaCompare*
                                Compare two molecules end to end. A circular
                                record is rotated into phase first (and
                                reverse-complemented if that scores better),
                                so a different origin is not a difference;
                                the header says what was applied.
:DnaAlignAnnotate                                          *:DnaAlignAnnotate*
                                Write the last alignment's differences onto
                                the record as features (`align.annotate_type`,
                                `variation` by default) in one undo step.

Modes ~
  semi    the query is placed inside the record: the record's end gaps are
          free. The default, and what a read wants.
  global  both sequences are aligned end to end, every end gap charged.
  local   the best-scoring segment of each sequence.
Both strands are tried unless `strand=plus` or `strand=minus` is given. On a
circular record a `semi` or `local` placement may run through the origin; the
header then says so and the coordinates wrap.

The view ~
Reference row with coordinates, match row, query row, in blocks of
`align.width` residues (0 = fit the window), mismatches and gaps highlighted.
Above it: the differences, each naming the feature, codon and effect
(`1255 G>A  tet codon 390 TGG>TGA W390* nonsense`); the features hit, with
silent / missense / nonsense / frameshift and any premature stop; and a
summary. An alignment longer than `align.full_limit` columns shows only
`align.context` residues around each difference.

  ]d  [d    next / previous difference
  <CR>      go to that difference in the record
  ga        write the differences onto the record
  q         close

What is modelled ~
Scores are `align.match` / `align.mismatch` for nucleotides and BLOSUM62 for
proteins, with `align.gap_open` charged once per gap plus `align.gap_extend`
per base. Pairs within `align.max_cells` are aligned over the full matrix;
larger ones inside a band around the diagonals that shared 11-mers vote for,
which needs the two sequences to be versions of each other — unrelated long
sequences are declined rather than aligned badly. There is no multiple
alignment, no consensus, and no trace (.ab1) reading.

The engine agrees with Biopython's PairwiseAligner on all 1,097 cases of the
committed corpus; see docs/alignment_report.md.

15. LARGE RECORDS                                              *plasmid-large*

A bacterial genome is a quarter of a million rows of sequence. Above
`linear.window.threshold` residues the linear view counts how many rows the
buffer has without laying any of them out, then lays out only the rows a
window is showing, building them as you scroll and dropping them again behind
you.

Nothing about the view changes: coordinates, feature tracks, translations,
selection, search, restriction sites, primers, alignment and editing behave
as they do on a plasmid. A spec compares the two layouts row by row across
the fixture corpus and a corpus of real genomes; see
docs/large_records_report.md.

Measured on E. coli K-12 (NC_000913.3, 4,641,652 bp, 9,285 features) at 120
columns: opening takes 1.0 s and holds 112 MB, against 5.3 s and 710 MB
laying the whole record out; a page of scrolling 0.9 ms, a jump 6.8 ms.

Resizing the window costs nothing at all unless it changes the number of
residues per line, which stays a multiple of ten so that the ruler and the
end-of-line numbers stay round: at 120 columns that genome has the same
layout anywhere from 115 to 125, and dragging a border inside that range is
0.04 ms. A resize that does change it lays the record out again (0.25 s on
that genome), and waits `resize_debounce` milliseconds first so that a drag
pays for one layout rather than one per column.

                                                        *plasmid-large-config*
    linear = {
      window = {
        enabled = "auto",     -- "auto" | true | false
        threshold = 300000,   -- residues above which "auto" windows
        margin = 2,           -- screens built either side of the window
        cache_blocks = 512,   -- lines kept laid out behind you
      },
    },
    resize_debounce = 80,     -- ms to wait before laying out at a new
                              -- window width; 0 lays out at once

:DnaInfo says whether the record you are looking at is windowed, and
:checkhealth plasmid reports the threshold.

THE GENOME RING                                                 *plasmid-ring*

The circular map draws one arc per feature while an arc is still wider than a
braille dot. Above `circular.atlas.threshold` residues it is not, and there
are more features than the rings can hold, so the map draws a genome atlas
instead. From the backbone inwards: feature density on the forward strand,
feature density on the reverse strand, GC content against the record's mean
(outwards above it, inwards below), and GC skew (G-C)/(G+C), outwards
positive and inwards negative. Coordinate ticks sit outside the backbone at a
round interval -- every 500 kb on a bacterial genome, every kilobase on a
plasmid.

A bin is a round number of bases, the finest that fits one bin per character
cell around the ring, and the same bin is the window GC and skew are measured
over. The second header row states it, names the rings, and accounts for every
feature: in the rings, hidden as annotation history, or past the end of the
sequence. Nothing is dropped silently at either scale.

On a circular DNA record whose cumulative (G-C) swings by at least 0.4% of its
length, the two places it turns are marked and named `origin (skew)` and
`terminus (skew)`: the forward strand is the leading strand from the origin
round to the terminus, so the running sum falls to its minimum at one and
rises to its maximum at the other. On E. coli K-12 the minimum lands 744 bp
from the annotated oriC at 25 kb bins. A record with no replication signal is
not given one.

Labels at this scale are landmarks only -- a replication origin, the rRNA
operons (one label per operon, not one per gene), then the largest features --
at most `circular.atlas.landmarks` of them.

                                                         *plasmid-ring-config*
    circular = {
      atlas = {
        enabled = "auto",     -- "auto" | true | false
        threshold = 500000,   -- residues above which "auto" draws the atlas
        landmarks = 12,       -- most features named on the ring
      },
    }

"auto" decides on the record's length alone, so resizing a window never
changes which map you are looking at. docs/ring_report.md has the measured
build times, what the specs check, and the evidence that plasmid-scale maps
render exactly as they did before the atlas existed.

THE OVERVIEW                                                *plasmid-overview*

:DnaOverview [bases-per-row]                                    *:DnaOverview*
                                The whole record on one screen: one row per
                                span, with a strip of cells showing which
                                strands carry features where, the per-strand
                                counts, and as many feature names as fit.
                                Again to close. `gm` does the same.
:DnaRegion {start}..{stop}                                        *:DnaRegion*
                                Go to a region of the record and select it.

Cells are coloured by the most important feature in them, with the colours
the other views use. A cell is an upper half block where only the forward
strand has features, a lower half block where only the reverse does, a full
block where both do, and a dot where neither does. `▶` in the gutter marks
the row the sequence view's cursor is on, `┃` the rest of what it shows.

With `overview.span = "auto"` the span is the smallest round number -- 1, 2
or 5 times a power of ten -- that fits the record in the window, and the
header says what it is: 10 kb a row for a 230 kb chromosome, 200 kb a row for
a bacterial genome. `:DnaOverview 110000` forces a span, and the view then
scrolls if the record needs more rows than the window has.

  <CR>        go to this region in the sequence view
  <LeftMouse> go to the region under the pointer
  q           back, exactly where the sequence view was

    overview = {
      span = "auto",          -- bases per row, or "auto"
      min_span = 10,          -- the finest span "auto" will pick
      strip = "auto",         -- columns of picture per row
      labels = true,          -- name features in a row when there is room
      counts = true,          -- per-strand feature counts
      keymaps = { jump = "<CR>", close = "q", click = "<LeftMouse>" },
    }

20. FILES AND FIDELITY                                         *plasmid-files*

Formats: GenBank/GenPept, FASTA (DNA, RNA, protein), and SnapGene .dna,
.rna and .prot (read; written back only for files opened from SnapGene).
Protein records use the linear view only, with positions in aa.

Files are written back byte-for-byte when unmodified: header blocks, every
feature's original lines, and the file trailer are kept verbatim. Changed parts
are regenerated in NCBI layout. Writing to a name with another format's
extension converts the file (`:w copy.fasta`). FASTA keeps lowercase
soft-masking, line width, and CRLF line endings.

SnapGene text fields are HTML; the plugin decodes entities for display and
encodes them on write. Edited primers cannot yet be written to SnapGene files
(the write is refused rather than losing them).

21. KNOWN ISSUES                                              *plasmid-issues*

Neovim 0.12.2 headless (`nvim --headless`, `nvim -l`) can crash in
`:redraw!` after a message wider than 'columns'; this happens without the
plugin. The plugin truncates its own messages to the available width.

Hairpin and dimer free energies are estimates from published nearest-neighbour
tables, not primer3's values; they agree on whether to warn in 93.0-99.1 % of
cases (|plasmid-oligo|). Tm and Ta match NEB's calculator exactly.

:DnaEnzymeImport follows REBASE's documented EMBOSS layout as Biopython's
converter reads it; it is tested on fixtures and on files generated from
Biopython's enzyme data, not yet on a downloaded REBASE release.

Opening a large record still counts every block of it to learn how long the
buffer is: 0.01 s of the 1.0 s E. coli K-12 takes, growing with the record.
Most of the rest is parsing the file. A resize that changes the residues per
line lays the record out again (|plasmid-large|). The circular view is built
whole whatever the record's size; at genome scale the base composition behind
its rings is read once per record and bin width and then cached, so a resize
that lands on the same round bin width does not pay for it again
(|plasmid-ring|).

NCBI occasionally answers with HTTP 429 or a transient "Search Backend
failed"; requests are retried with backoff, but a busy period can still
surface an error. Try again, or set an API key.

Neovim 0.12.2 can crash ("double free or corruption") when the experimental
`nvim__redraw({ buf = ... })` targets a buffer while another window is
current; the plugin repaints through extmarks instead.
